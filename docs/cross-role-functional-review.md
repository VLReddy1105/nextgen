## Shared controls and concrete changes

- Header and sidebar account controls now use the same popover. Profile/Settings close it; Account/Verification use real section anchors. Logout retains POST /auth/signout.
- One open popover at a time; outside pointer, Escape, focus departure, route change and link activation close it. Escape restores trigger focus. Mobile sidebar account navigation also closes the dialog.
- Parent link navigates and expands; the separate chevron toggles. Active child routes auto-expand their parent; active links expose aria-current. Reviewed application submenu added. Event status submenus now match the management filters.
- Removed the hardcoded NEW badge. AI Tools remains an explicit preview, as required by regression scope; no unavailable AI action was invented.
- Organization-backed forms select the matching role context instead of the first row. Founder space creation no longer passes an unsupported startup organization. Verified campus creation remains gated. The University count query now selects the university row rather than an unrelated owned organization; no request scheduling or aggregation architecture changed.
- Student Today includes registered events and non-cancelled sessions. Overview labels identify published opportunities, active applicants, joined spaces and published upcoming events. Duplicate Company overview applicants and Mentor affiliation context cards are suppressed in the right panel.
- Existing Editor success feedback clears when fields change, avoiding stale “Saved” feedback for unsaved edits.
- Removed the extra unconditional Request mentorship button from the detail page; the existing card already gates the action by availability and connection status.

## Schema-dependent blocker: support for other roles

The existing support_reports table exists, but reports_insert permits only user_id=auth.uid() AND workspace_ready('student'). Its category constraint is problem/opportunity/support. There is no urgency field or support-response workflow.

Exact requirement: permit ready Mentor/Company/University/Founder accounts to insert only their own reports, while retaining recipient/self read isolation and the existing grants. Smallest proposed future migration: replace only reports_insert with an own-user predicate plus workspace_ready() (or an explicit five-role allowlist). Do not broaden SELECT or add service-role writes. No migration was created or applied here.

Student topic labels are stored as a message prefix and mapped to the existing three category values; no schema change is necessary. The other four roles receive role-specific FAQs and working navigation, but no submit button that would predictably fail RLS. Their topic catalogs are prepared in workspace-help.ts for a separately authorized reporting implementation. Urgency controls and promises of response time are omitted because no backend supports them.

## Cross-role evidence and boundaries

The isolated database suites execute the existing migrations in disposable PostgreSQL (PGlite), then exercise publishing/application status/history/notifications, campus eligibility, event registration, project invitations and acceptance, community activity, university invitations/domain decisions, Mentor consent/sessions, affiliation in both directions, Mentor openings/applications, helper ACLs and mark-one/mark-all isolation. No hosted writes are part of these tests.

Browser fixture suites exercise existing forms and role contexts without hosted accounts. Authentication/unit tests verify admission and redirect behavior; they do not prove live credentials, mail delivery or hosted deployment health. Founder is intentionally not given Company Talent, Applicants or campus controls. Although lower-level posting functions accept Founder organization ownership, adding a new Founder recruitment module is outside the existing role workspace baseline.
